AI / LLM Systems Engineer с практическим опытом проектирования production-сервисов, гибридных RAG-пайплайнов и систем сопоставления сущностей.

Более 2.5 лет опыта в инфраструктуре и системном администрировании (Linux, кластерный мониторинг Zabbix/Grafana, сегментация сетей 802.1Q VLAN, безопасность и ГОСТ ЭЦП) и коммерческий опыт Python-бэкенд разработки в сфере Healthcare (интеграция лабораторных анализаторов, ЛИС, обработка потоковых протоколов).

- Self-hosted инференс открытых моделей (Ollama, vLLM, Qwen) в изолированном контуре с соблюдением требований 152-ФЗ.

## Коммерческий опыт и результаты

- **SkyLab Med AI: Конвейер автоматической расшифровки лабораторных бланков** ([Архитектурный кейс](AI_LLM_PORTFOLIO.md#case-2-skylab-med-ai-zero-hallucination-clinical-report-interpretation)):  
  On-premise сервис расшифровки медицинских анализов по PDF-бланкам без передачи конфиденциальных данных во внешние API.
  - Архитектура из 5 изолированных слоев: геометрическое извлечение таблиц PDF без OCR (`pdfminer.six`), валидация числовых значений (V0–V10), 112 неизменяемых контрактов данных Pydantic v2, контур деперсонализации (отсечение ФИО и ПДн) и детерминированный Medical Engine на базе верифицированных врачами правил.
  - Исключение риска искажения медицинских данных: логика интерпретации отделена от модели. Локальная LLM (Qwen через Ollama) формирует только стилистическое резюме, вывод которого валидируется кодом на совпадение цифр и диапазонов.
  - Надежность подтверждена 218 автоматическими unit-тестами. Протестировано на 139 реальных бланках (15 пакетных PDF, 2023 показателя) — 0 аварийных завершений, 0 расхождений с лабораторными референсными значениями.

  - Детерминированные доменные фильтры на Python до вызова LLM (разграничение качественного/количественного ПЦР, типа биоматериала, антител IgM/IgG), отсекающие 90%+ некорректных пар без затрат ресурсов модели.
  - Локальная модель `qwen3:8b` (Ollama) в режиме рассуждения со строгим JSON Schema; сократила число ложных срабатываний с 29 до 3.
  - На эталонном датасете из 196 размеченных анализов: **Precision 97.5%**, **Recall 91.8%**, покрытие каталога с ценой **88.1%** (578 из 656 услуг).

## Избранные инженерные проекты

### 1. [hybrid-rag: Гибридный RAG по Трудовому кодексу с детерминированной валидацией и калибровкой отказа](https://github.com/DelixeamI/hybrid-rag)

[![CI](https://img.shields.io/github/actions/workflow/status/DelixeamI/hybrid-rag/ci.yml?branch=main&label=CI&logo=github)](https://github.com/DelixeamI/hybrid-rag/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/License-MIT-yellowgreen.svg)](https://github.com/DelixeamI/hybrid-rag/blob/main/LICENSE)
[![python](https://img.shields.io/badge/python-3.12-blue.svg)](https://github.com/DelixeamI/hybrid-rag/blob/main/pyproject.toml)
[![tests](https://img.shields.io/badge/tests-130-brightgreen.svg)](https://github.com/DelixeamI/hybrid-rag/tree/main/tests)

Сервис ответов на юридические вопросы по Трудовому кодексу РФ с детерминированным контролем фактологии и тестами, подтверждающими качество на каждом шаге. Основная инженерная задача в RAG — не написание системного промпта, а надежный ретривал, калиброванный порог отказа на нерелевантных вопросах и строгая проверка того, что каждый ответ подтвержден источником.

- гибридный ретривер: комбинация плотного поиска (dense multilingual-e5-small с pgvector) и разреженного BM25 на полнотекстовых лексемах PostgreSQL (`russian`), объединенных через Reciprocal Rank Fusion (RRF, top-20) с параметрами $k=10$ и весом плотного поиска 3.0;
- cross-encoder реранкер: модель `BAAI/bge-reranker-v2-m3` отбирает top-5 релевантных чанков, повышая Recall@5 с 84.2% до 93.4% и MRR с 0.795 до 0.898 на полном тексте кодекса;
- калиброванный отказ от генерации: порог уверенности реранкера ($0.0066$) отсекает нерелевантные запросы до вызова LLM, обеспечивая 100% корректных отказов на `no_answer` вопросах и 1.3% ложных отказов на ответимых;
- детерминированный валидатор фактов и цитат: сопоставление номеров статей, сроков и чисел с единицами измерения по цитатам фрагментов, гарантирующее точность фактов в 92.0% ответов и безопасную деградацию до списка статей при непрохождении проверки;
- кассетный офлайн-инференс: класс `RecordedLLM` воспроизводит сохраненные ответы без обращения к внешним API, что позволяет запускать полный цикл валидации качества в CI без секретов и внешних задержек;
- асинхронный FastAPI-сервис: эндпоинты `/ask` и `/health`, структурированные JSON-логи с разбивкой латентности по стадиям (ретривал, реранк, генерация, валидация) и идемпотентный ингест по sha256 документа.

130 тестов, работа без внешней сети и API-ключей. В [DESIGN.md](https://github.com/DelixeamI/hybrid-rag/blob/main/DESIGN.md) зафиксированы архитектурные альтернативы, границы применимости и измеренные компромиссы.

### 2. [entity-cascade: Каскадный пайплайн сопоставления номенклатуры товаров с оптимизацией компромисса автоматизации и точности](https://github.com/DelixeamI/entity-cascade)

[![CI](https://img.shields.io/github/actions/workflow/status/DelixeamI/entity-cascade/ci.yml?branch=main&label=CI&logo=github)](https://github.com/DelixeamI/entity-cascade/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/License-MIT-green)](https://github.com/DelixeamI/entity-cascade/blob/main/LICENSE)
[![python](https://img.shields.io/badge/python-3.12-blue)](https://github.com/DelixeamI/entity-cascade/blob/main/pyproject.toml)
[![tests](https://img.shields.io/badge/tests-169_passed-brightgreen)](https://github.com/DelixeamI/entity-cascade/tree/main/tests)

Каскадный конвейер сопоставления прайс-листов поставщиков с эталонным каталогом продукции и тесты, верифицирующие его границы. Ключевая инженерная задача здесь — не отправка всех строк в дорогую LLM, а математически выверенный поиск границы между долей автоматизации и точностью системы на отложенной выборке.

- трехзонная архитектура маршрутизации: автоматическое подтверждение (`auto_match`) для пар с высоким скором и отрывом (margin), серая зона (`gray band`) для разрешения локальной LLM и эскалация оператору (`human_review`) для сомнительных строк;
- двухстадийный гибридный поиск: плотные векторные эмбеддинги (`bge-small-en-v1.5`) и BM25 с ранговым слиянием RRF (top-20), дополненные cross-encoder моделью (`ms-marco-MiniLM-L-6-v2`);
- доменные фичи и эвристики: выделение кодов моделей и брендов с расчетом запаса уверенности между кандидатами, что повышает долю автоматизации с 28.3% до 67.7% при сохранении точности 96.7%;
- локальный LLM-арбитр с JSON-схемой: квантованная модель `qwen2.5:14b` через Ollama с Pydantic-контрактом, закрывающая 45.4% серой зоны с точностью 84.8% при $0.00 расходов на облачные токены;
- детерминированная подгонка порогов (`fit_thresholds`): калибровка порогов срабатывания строго на валидационной выборке с оценкой нижней границы Вильсона (Wilson 95% bound) для защиты от переобучения;
- контроль переноса домена: оценка устойчивости калибровки при применении к новому датасету (Amazon-Google) без переобучения, с прозрачной фиксацией изменения метрик при смене домена.

169 тестов, запуск без сети и API-ключей. В [DESIGN.md](https://github.com/DelixeamI/entity-cascade/blob/main/DESIGN.md) задокументированы архитектурные компромиссы, цена каждого решения и поведение системы при отказе внешних провайдеров.
